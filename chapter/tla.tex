\section{事务操作语义的\TLAPlus 表达}
\subsection{状态模型}

第二章已经介绍了 \TLAPlus 与 TLC 的基本概念。本章在此基础上进一步面向本文提出的事务模型，给出事务操作语义的 \TLAPlus 表达方式。形式化规约仍采用“初始状态 $Init$ + 状态转移 $Next$ + 安全断言”的组织范式，但其中涉及的状态变量、动作定义与约束条件均围绕混合隔离级别事务的执行过程展开。

在状态建模上，本文将事务执行过程抽象为一个离散状态机。系统状态不仅包含全局键值存储及其版本历史，还包含事务缓冲区、事务快照、操作历史以及客户端依赖信息等辅助变量。通过这种建模方式，系统在任意执行时刻的可见状态都能够被形式化描述，从而为后续一致性公理的检查提供统一的语义基础。完整模块代码可见 \url{https://github.com/ZhangJihua0327/mil-tla-verify} 仓库。

\section{一致性公理和隔离级别约束}

在前文中，本文已经介绍了 \TLAPlus 规约语言及 TLC 模型检查器的基本概念与设计范式。

在本节中，本文进一步说明如何利用 \TLAPlus 构建一个面向混合隔离级别操作语义的严格验证框架。在这一框架下，形式化约束的构造主要包括两个方面：其一是将事务执行历史转化为抽象执行中的 $\text{VIS}$ 与 $\text{AR}$ 关系；其二是将一致性公理与隔离级别约束转化为可由 TLC 检查的逻辑断言。
\subsection{状态变量与动作定义}
\subsubsection{状态模型}

定义操作语义的第一步是构造状态模型。本文使用一组状态变量来表示系统的当前状态，这些变量共同描述事务状态、数据项取值、版本可见性以及相关依赖关系。通过对这些组件作出明确约束，可以较为准确地刻画系统在任意时刻的运行状态。

重要的变量有：
\begin{itemize}
    \item \texttt{store}: 全局键值存储，模拟数据库的持久化状态。它是一个映射，键是 Keys，值是版本历史（包含值、提交时间戳 cts、写入者）。
    \item \texttt{tx\_buffer}: 事务的本地写缓冲，模拟事务在提交前对数据的本地修改。
    \item \texttt{tx\_snapshot}: 事务的读取快照版本，决定了事务能看到哪些数据。
    \item \texttt{op\_seq}: 记录操作的历史序列，用于后续的公理化验证。
\end{itemize}

通过上述变量，可以构建一个较为完整的状态模型，并据此进一步形式化描述事务操作语义。

\subsubsection{核心状态转换动作 (Transition Actions)}
操作语义的核心逻辑可归纳为三个主要的 \TLAPlus 动作定义：

\textbf{A. 事务开始 ($StartTx(t)$)}

该动作形式化描述了事务获取读取视图（Read View）的过程：
\begin{itemize}
    \item 根据事务的隔离级别 ($Workload[t].level$)，决定 $tx\_snapshot[t]$ 的值。
    \item 例如：SI (Snapshot Isolation) 获取当前的全局 $shard\_ct$（时间戳）。
    \item RA (Read Atomicity) 获取客户端上一次提交的时间 $client\_last\_commit$。
    \item 将事务状态 $tx\_status$ 设为 "Active"。
\end{itemize}

上述定义直接体现了不同隔离级别在快照来源上的差异：PC、SI 和 SER 从全局提交时钟获取一致快照，CC 与 PSI 继承会话依赖，而 RA 仅依赖客户端最近一次提交时间。这种划分将第三章中的语义规则映射为可执行的状态更新条件，也是后续验证 $\text{VIS}$ 构造是否正确的重要基础。

\textbf{B. 执行操作 ($ExecuteOp(t)$)}

该动作给出了读写操作的具体语义，并根据 $Workload$ 中预定义的操作类型进行分支：

\begin{enumerate}
    \item \textbf{读操作 ($op.type = "R"$):}
          \begin{itemize}
              \item \textbf{本地优先读取:} 首先检查 $tx\_buffer[t][op.key]$（即写后读 Read-Your-Writes 语义）。
              \item \textbf{快照读取:} 如果本地没有，则调用辅助算子\\ $MaxVersion(store[op.key], tx\_snapshot[t])$。这意味着它会在全局存储的版本历史中，找到提交时间戳小于等于事务快照的最新版本。
              \item \textbf{记录历史:} 将读取结果追加到 $op\_seq$，用于验证。
          \end{itemize}
    \item \textbf{写操作 ($op.type = "W"$):}
          \begin{itemize}
              \item \textbf{写缓冲:} 并不会立即修改全局 $store$，而是更新 $tx\_buffer$。
              \item \textbf{记录历史:} 将写操作追加到 $op\_seq$。
          \end{itemize}
\end{enumerate}

该定义保留了两个最关键的语义点。其一，读操作优先检查本地写缓冲，以保证事务内部满足 Read-Your-Own-Writes；其二，若本地不存在对应写入，则利用 \texttt{MaxVersion} 从满足快照上界的版本集合中选取最新版本。由此，版本可见性被归约为一个可由 TLC 直接枚举和检查的选择过程。

\textbf{C. 提交事务 ($CommitTx(t)$)}

该动作形式化描述了提交协议，其中包括并发控制与原子性要求：

\begin{enumerate}
    \item \textbf{冲突检测 ($HasConflict$):}
          \begin{itemize}
              \item 定义了谓词 $IsConcurrent(t\_other)$ 来识别并发事务。
              \item 检查是否存在其他并发已提交的事务，其写入集（Writes）与当前事务的检查集（Checkset/ReadSet）有冲突。这对应了乐观并发控制（OCC）的验证阶段。
          \end{itemize}
    \item \textbf{状态更新:}
          \begin{itemize}
              \item \textbf{Abort:} 如果有冲突，状态变为 "Aborted"。
              \item \textbf{Commit:}
                    \begin{itemize}
                        \item 递增全局时间戳 $shard\_ct$。
                        \item \textbf{原子写入:} 将 $tx\_buffer$ 中的数据合并到全局 $store$ 中，生成带有新时间戳的新版本。
                        \item 更新客户端依赖 $client\_dep$。
                    \end{itemize}
          \end{itemize}
\end{enumerate}

在提交阶段，模型通过 \texttt{HasConflict} 谓词统一表达 PSI、SI 与 SER 等隔离级别所需的并发校验，并在校验通过后以单个状态跃迁完成提交时间分配与新版本写入。由于 \TLAPlus 以状态转移为核心，上述定义能够将“冲突检测”与“原子提交”纳入同一条可验证路径，从而避免在正文中展开与证明主线关系不大的工程性细节。

不同于面向具体业务逻辑的程序语言，\TLAPlus 更关注状态转移结果本身。运行 \TLAPlus 代码时，TLC 模型检查器会穷举所有可能的状态转移路径，并检查这些路径是否满足预先定义的安全属性。通过配置不同的安全属性，便可以验证系统在不同隔离级别下是否满足相应约束，从而验证模型设计的正确性。

\section{模型检查实验与结果}
\subsection{测试方式和测试结果}

测试用例只需通过 \texttt{INSTANCE MixedIsolation WITH ...} 语法注入负载，验证引擎即可启动运行。在验证过程中，TLC 模型检查器会探索所有通过 \texttt{Next} 产生的合法状态转移路径。TLC 的穷举能力使网络延迟、乱序提交与快照交错等情形均能够被覆盖。一旦在某个微观并发场景下发现生成的执行图违反 \texttt{OperationalSafety == IsConsistentExecution} 断言，模型检查器就会立即停止，并输出精确的反例路径追踪报告（Error Trace File），以协助开发者定位并修复并发漏洞。

本文在实验阶段采用 SmallBank 负载对混合隔离级别模型进行实例化，原始测试用例如图~\ref{fig:tla-smallbank} 所示。通过注入该负载，TLC 模型检查器能够验证系统在该场景下是否满足所定义的安全属性，并据此发现潜在的并发问题。实验结果表明，在 SmallBank 负载下，系统满足预先定义的安全属性，且未发现违反一致性要求的潜在并发问题。这说明该操作语义在该负载下能够保证事务满足目标隔离级别的约束。

\begin{figure}[htbp]

\end{figure}

该测试用例给出了一个最小但具有代表性的混合隔离级别验证场景。图中定义了两个并发事务，其中事务 $T_1$ 以 PSI 隔离级别读取 \texttt{checking} 与 \texttt{savings} 两个账户并更新储蓄账户余额，事务 $T_2$ 则以 SER 隔离级别对相同数据项执行读取与写入操作。这样一组负载既保留了 SmallBank 场景中典型的账户读写依赖，又能够显式触发跨事务可见性、检查集冲突以及不同隔离级别交织执行下的一致性约束，因此适合作为 TLC 模型检查的实例化输入。

\section{本章小结}

本章围绕支持混合隔离级别机制的 \TLAPlus 建模与验证展开。首先给出了事务操作语义的 \TLAPlus 表达方式，说明状态变量与核心动作如何共同描述事务执行过程；其次构建了抽象执行关系、一致性公理与隔离级别约束的形式化断言；最后结合模型检查实验及结果分析，验证了本文所设计的操作语义能够保证事务满足目标隔离级别的要求，并为后续原型系统实现提供形式化依据。
