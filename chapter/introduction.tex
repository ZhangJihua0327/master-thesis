\chapter{绪论}

\section{研究背景与研究意义}

在互联网应用持续演进的背景下，数据库系统已经成为信息基础设施中的核心组成部分，几乎支撑着所有关键业务系统的运行\cite{sql-for-Ai}。从在线交易、社交网络到云计算与人工智能应用，海量数据的高效存储、实时访问与可靠管理，直接影响上层业务的性能、可用性与安全性\cite{Cattell2011, Stonebraker2010}。随着互联网业务规模持续扩大，分布式和云原生架构快速普及，传统集中式数据库在扩展性、可用性以及运维成本等方面逐渐暴露出难以克服的瓶颈，对于满足大规模在线服务与大数据业务需求显得愈发吃力\cite{Agrawal2016}。分布式数据库正是在这样的背景下应运而生。通过在多节点上对数据进行分片与复制，分布式数据库能够实现水平扩展与高可用，已成为支撑大规模在线服务与数据密集型业务的重要技术路径\cite{Ozsu2011}。

事务（Transaction）是数据库系统中保障数据一致性与隔离性的核心机制，也是支撑上层业务正确性的基础\cite{Gray1993}。在数据库系统中，事务被视为一个逻辑工作单元，由一系列操作构成，其目标是在并发访问和系统故障存在的条件下，仍保持数据的完整性与一致性。经典数据库理论通常以 ACID 特性来描述事务的基本要求\cite{acid,Haerder1983}：
\begin{itemize}
      \item \textbf{原子性（Atomicity）}：事务中的所有操作要么全部执行成功，要么全部不执行。若执行过程中发生错误，系统必须回滚到事务开始前的状态，避免出现部分完成的中间状态。
      \item \textbf{一致性（Consistency）}：事务执行前后，数据库应当从一个一致状态转换到另一个一致状态，不能破坏主键、外键或业务规则等完整性约束。
      \item \textbf{隔离性（Isolation）}：多个事务并发执行时，每个事务都不应受到其他事务中间状态的干扰，系统需要通过并发控制机制保证结果与某种约定的顺序执行相一致。
      \item \textbf{持久性（Durability）}：一旦事务提交，其对数据库的修改应被永久保存，即使系统发生故障也不应丢失。
\end{itemize}

然而，在分布式环境中，实现事务语义的代价显著提高。由于数据分布在多个物理节点上，网络延迟、节点故障与分区容错等问题使严格的一致性保障变得复杂且昂贵。因此，分布式数据库往往需要在一致性、可用性与分区容错之间进行权衡\cite{Brewer2000, Gilbert2002}。在这一背景下，隔离级别设计逐渐成为系统在正确性与性能之间进行取舍的重要手段。

对分布式场景中的事务处理而言，单一隔离级别往往难以同时满足所有业务需求。混合隔离级别（Mixed Isolation Level，MIL）允许不同事务根据自身业务语义与性能需求，在同一系统中运行于不同隔离级别之下\cite{Terry2013, Bailis2014}。例如，对一致性要求极高的转账事务可以采用可串行化隔离级别，而对性能敏感、但允许一定语义放宽的日志分析事务则可以采用较弱隔离级别。这样，系统就有机会在保障关键事务正确性的同时，释放其他事务的并发潜力。

需要指出的是，当前一些数据库产品已经支持“不同事务可配置不同隔离级别”的工程能力，但这并不等同于混合隔离级别已经具备统一、清晰且可验证的语义规范。现有理论基础，例如基于冲突和视图可串行化的理论，通常默认所有事务运行于同一隔离级别之下；在多版本并发控制（MVCC）环境中，不同可见性规则事务之间的交互行为，例如 SER 与 SI、RR 等级别之间的组合，仍缺乏统一而完备的形式化描述。近期 Bouajjani 等人的工作\cite{bouajjani2025complexity}更多从黑盒角度测试数据库对隔离级别的保证，而如何建立面向系统内部机制的白盒分析方法和形式化定义，仍然是值得深入研究的重要方向。

因此，本文将问题进一步聚焦为：如何为混合隔离级别事务建立统一语义模型，如何将该模型落实为可执行、可验证的系统操作语义，以及如何通过原型实现与实验评估说明该机制的工程可行性与性能收益。围绕这一问题展开研究，对于构建兼顾理论严谨性与工程可行性的分布式数据库系统具有明确的学术价值与实际意义。

\section{研究现状与挑战}
\subsection{研究现状}

围绕分布式事务、隔离级别与形式化验证的研究，现有工作已经在事务理论、并发控制、多版本机制以及一致性建模等方面积累了较为扎实的基础\cite{Gray1993,berenson1995critique,Terry2013,Bailis2014,Schultz2015}。然而，面向混合隔离级别场景的研究仍然相对不足，尤其在统一语义定义、形式化验证方法以及理论与实现衔接方面仍存在明显空缺。

首先，现有研究对混合隔离级别的语义刻画仍不充分。传统隔离级别理论大多建立在“所有事务运行于同一隔离级别”的前提之上，其核心目标是描述单一隔离策略下允许或禁止的异常行为。然而，在混合隔离级别场景中，不同事务依据不同可见性规则并发执行，事务之间的依赖关系、冲突传播路径以及可接受执行结果的判定条件都会显著复杂化。现有研究虽然已经开始关注这一问题，但对于不同隔离级别事务交互时的统一语义定义、异常边界及其判定准则，尚未形成充分一致的理论框架\cite{bouajjani2025complexity}。

其次，现有研究在形式化验证层面仍存在不足。已有工作通常能够针对特定一致性模型、特定隔离级别或局部并发控制机制进行分析与证明，但对于混合隔离级别下分布式事务系统的整体行为，尤其是跨分片事务执行过程中状态演化、版本可见性与提交约束之间的联动关系，仍缺乏系统性的形式化表达与验证方法。这使得很多系统设计只能停留在经验性论证或局部正确性分析层面，难以对复杂并发场景下的关键安全性质给出严格保证。

再次，现有研究在理论模型与工程实现之间仍存在明显断层。部分研究侧重一致性公理、异常定义或抽象执行模型，能够从理论层面解释并发行为；另一些工作则聚焦数据库系统实现，通过事务协调、时间戳定序、MVCC 或两阶段提交等机制提升性能与一致性保障能力。然而，两者之间往往缺乏稳定、清晰的映射关系，即理论模型难以直接指导系统实现，而工程系统中的关键设计决策也缺少可回溯的语义支撑。这种脱节限制了研究成果的可验证性、可复现性与可推广性。

最后，现有研究对混合隔离级别系统的实验评估仍不够系统。许多工作主要围绕单一隔离级别、单类负载或特定系统设定展开性能测试，对于不同隔离级别混合配置下系统吞吐量、事务延迟、一致性风险与扩展能力之间的关系缺乏更系统的实验分析。特别是在跨分片事务、复杂读写依赖以及多种业务负载并存的条件下，如何定量评估混合隔离级别机制在正确性与性能之间的权衡效果，仍然是当前研究中的薄弱环节。

从工程实践角度看，现有主流数据库产品在分布式事务处理与混合隔离级别支持方面也体现出不同的设计路径。传统关系型数据库如 MySQL 与 PostgreSQL 具备成熟的 ACID 能力，但其分布式事务通常依赖 XA 或相关协调机制，在跨节点场景下容易遭遇较高的协调开销\cite{Lampson1976,Perkins2011}。Redis 等高性能键值存储系统强调水平扩展与高吞吐，但其事务能力主要局限于单分片操作\cite{Carlson2013}。FoundationDB、Google Spanner 和 TiKV 等 NewSQL 系统则提供了跨节点强一致事务处理能力\cite{Pavlo2011}，但其并发控制协议通常建立在统一隔离级别假设之上，对混合隔离级别的统一语义支持仍不充分。以 Cassandra 与 DynamoDB 为代表的 AP 型数据库则更强调高可用与分区容错，在强一致事务处理方面存在架构层面的限制\cite{DeCandia2007,Lakshman2010,Vogels2009}。

综上，当前研究虽然为分布式事务处理和一致性保障提供了重要基础，但在混合隔离级别场景下，仍然存在语义定义不统一、形式化验证不足、理论与实现衔接不紧密以及实验评估不系统等问题。因此，有必要围绕统一语义建模、形式化正确性验证、原型系统实现与实验评估构建一体化研究路径，以增强相关研究的严谨性、可解释性与工程可行性。

\subsection{研究挑战}

基于上述研究现状，本文将问题收束为以下三个彼此衔接的关键挑战。

首先，混合隔离级别缺乏统一语义模型。现有隔离级别理论大多建立在所有事务运行于同一隔离级别的前提之上，而在混合隔离级别场景中，不同可见性规则的事务并发执行，会使事务间的依赖关系、冲突传播路径以及可接受执行结果的判定条件显著复杂化。因此，如何为不同隔离级别事务的并发交互建立统一、严谨的语义框架，是本文首先要解决的理论问题。

其次，统一语义缺乏面向系统行为的形式化验证手段。现有形式化方法通常针对特定一致性模型或局部并发控制机制进行分析，对于混合隔离级别下分布式事务系统的整体行为，尤其是跨分片事务执行过程中状态演化、版本可见性与提交约束之间的联动关系，仍缺乏系统性的形式化表达与验证方法。因此，如何构建覆盖混合隔离级别全局行为的形式化验证框架，是本文的第二个关键问题。

最后，形式化语义与工程实现之间仍存在明显断层。抽象的一致性公理与异常定义难以直接映射到具体的并发控制机制与系统实现，而工程系统中的关键设计决策也往往缺少可回溯的语义支撑。进一步地，混合隔离级别配置下不同事务对并发控制开销的要求并不相同，系统还需要在正确性与性能之间取得平衡。因此，如何建立理论模型、协议设计、系统实现与性能评估之间的稳定对应关系，是本文需要回答的工程落地问题。

围绕这三个挑战，本文分别从统一语义建模、形式化验证、原型系统实现与实验评估四个层面展开研究，以形成一条相互支撑的论证链路。

\section{本文的主要工作与不足}

本文采用分片（Sharding）架构\cite{thomson2012calvin}，参考 MongoDB 的设计思想，将数据水平切分并分布存储在多个物理节点上，以实现存储容量与处理能力的水平扩展。系统包含 Router、Shard 和 Config Server 等核心组件，其中 Router 作为客户端请求的统一入口，负责根据分片键将读写请求路由到对应节点；Config Server 负责维护全局元数据和分片映射关系。在此基础上，本文围绕混合隔离级别场景下跨分片事务处理的语义定义、正确性验证与系统实现展开研究。

本文的主要工作如下：
\begin{itemize}
      \item 面向分布式键值数据库场景，构建了混合隔离级别事务处理的统一语义描述框架，明确了不同隔离级别事务并发执行时的可见性规则、冲突约束与异常边界。
      \item 设计了支持混合隔离级别的分布式事务操作语义，并给出了与系统实现相对应的关键状态转换与并发控制机制。
      \item 使用 \TLAPlus 及 TLC 对事务操作语义、一致性公理和隔离级别约束进行形式化建模与模型检查，验证系统在给定模型范围内满足目标语义要求。
      \item 设计并实现了一个支持混合隔离级别的分布式键值数据库原型系统，完成了路由、分片、MVCC、HLC、跨分片事务协调及可观测性模块的工程实现。
      \item 通过基准实验评估不同隔离级别配置下的系统吞吐量与延迟表现，说明混合隔离级别机制在保证事务满足目标语义的前提下，能够有效提升系统整体执行效率。
\end{itemize}

尽管本文完成了从理论到原型系统的较完整研究，但仍存在以下不足：
\begin{itemize}
      \item 本文原型系统主要面向分布式键值数据库场景展开设计与验证，对于复杂查询优化、二级索引以及多模型数据支持等问题涉及较少，系统能力仍有进一步扩展空间。
      \item 形式化模型聚焦于混合隔离级别下事务语义与核心并发控制机制，对故障恢复、节点动态扩缩容以及副本复制等工程细节进行了必要抽象，尚未覆盖完整生产环境中的全部复杂因素。
      \item 实验评估主要验证了不同隔离级别配置下的吞吐量与延迟变化，对于超大规模集群、跨地域部署以及更多真实业务负载模式下的长期稳定性研究仍有待进一步展开。
\end{itemize}

\section{本文的组织结构}

第一章为绪论，主要介绍研究背景与研究意义，分析相关研究现状与面临的关键挑战，并概述本文的主要工作、不足与组织结构。

第二章为相关技术与理论，介绍数据库异常与隔离级别、一致性建模基础以及 \TLAPlus 与 TLC 等形式化验证相关技术，为后续章节奠定理论基础。

第三章讨论系统操作语义，从系统架构、混合逻辑时钟与事务操作语义三个方面给出支持混合隔离级别的分布式事务执行模型。

第四章围绕事务操作语言的 \TLAPlus 表达、一致性公理与隔离级别约束以及模型检查实验与结果展开，对第三章提出的操作语义进行形式化验证。

第五章介绍原型系统的架构设计与系统实现，重点说明关键模块的设计目标、实现机制与工程落地方式。

第六章通过实验验证混合隔离级别机制对系统性能的提升效果，分析不同部署拓扑与不同隔离级别配置下的吞吐量表现。

第七章对全文工作进行总结，并展望未来的研究方向。
