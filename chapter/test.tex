\chapter{基于分布式KV数据库原型的系统测试与验证}
本文基于前述原型系统，对不同隔离级别配置下的事务执行性能进行测试，以验证混合隔离级别机制相较于单一强隔离级别方案在吞吐量上的优势。本章首先介绍测试环境、节点部署方式与评价指标，然后给出三个数据集在两种部署拓扑下的吞吐量结果，并据此分析不同隔离级别配置的性能差异。

\section{测试环境概述}
数据库原型系统基于 Golang 开发，并通过 Docker 容器模拟分布式数据库集群。测试均在本地环境中完成，容器的 CPU 与内存配额保持一致，以避免资源分配差异对结果造成额外干扰。除测试客户端外，集群共部署 6 个服务节点，包括 2 个 Router 节点、3 个 Shard 节点和 1 个 Config 节点，其中 Config 节点主要负责元数据管理。

本文重点考察两种部署方式。第一种方式中，6 个服务节点全部部署在同一个可用区内；第二种方式中，6 个服务节点按每两个节点一组分散部署到 3 个可用区中。两种部署方式使用相同的事务负载与资源限制，因此测试结果的差异主要反映节点分散程度对分布式事务协调开销的影响。

\section{测试负载与评价指标}
为了更全面地考察系统在不同业务模式下的表现，本文选取了 Courseware、SmallBank 和 TPCC 三个数据集。三个数据集分别覆盖课程管理、银行转账和订单处理等不同类型的事务访问模式，能够反映混合隔离级别在多种典型负载下的适用性。

测试中比较了三种隔离级别配置：\textbf{SER} 表示所有事务均采用可串行化隔离级别；\textbf{SI-SER} 表示事务在快照隔离与可串行化之间混合执行；\textbf{MIAED} 则表示引入 MIA 策略后的混合隔离级别分配结果。MIA 是本组另一项工作，主要根据事务内容分析结果，在保证事务正确性的前提下尽量匹配满足要求的最低隔离级别；本文仅将其作为对照策略，不展开其内部方法。评价指标采用平均吞吐量（transactions per second, tx/s），用于衡量系统在稳定运行阶段的整体处理能力。

从图~\ref{fig:throughput-single-az} 可以看出，在所有服务节点部署于同一可用区时，SER 的平均吞吐量为 69.36 tx/s，SI-SER 提升到 74.51 tx/s，平均增幅约为 7.42\%。这说明即使只在 SI 和 SER 两个较强隔离级别之间进行混合调度，也已经能够缓解一部分由全局串行化带来的并发约束。相比之下，MIAED 的平均吞吐量达到 206.19 tx/s，相较于 SER 提升约 197.28\%，相较于 SI-SER 进一步提升约 176.74\%。在三个数据集上，这一趋势都十分稳定：Courseware 上 MIAED 相比 SER 提升约 197.94\%，SmallBank 上提升约 196.81\%，TPCC 上提升约 197.10\%。在所有节点集中部署于同一可用区时，事务协调路径较短，网络往返带来的额外等待较小，因此三种策略都能达到各自的最高吞吐量水平。

当服务节点分散部署到多个可用区后，整体吞吐量显著下降，但不同隔离级别之间的相对关系保持不变。SER 的平均吞吐量为 7.13 tx/s，SI-SER 为 7.62 tx/s，平均增幅约为 6.85\%；MIAED 则达到 21.17 tx/s，相较于 SER 提升约 196.81\%，相较于 SI-SER 提升约 177.78\%。分数据集来看，MIAED 在 Courseware、SmallBank 和 TPCC 上相较于 SER 的提升分别为 195.40\%、194.87\% 和 200.18\%。这表明，当 6 个节点分散到多个可用区后，跨区通信会明显放大分布式事务的协调成本，但混合隔离级别机制仍然能够持续带来接近 3 倍的吞吐量收益。

进一步比较两种部署方式可以发现，当节点由单可用区集中部署转为跨可用区分散部署后，三种策略的平均吞吐量均下降到原来的约 10\% 左右：SER 下降约 89.72\%，SI-SER 下降约 89.77\%，MIAED 下降约 89.73\%。这说明随着节点分散程度提高，事务提交路径被显著拉长，跨节点协调与通信等待的开销被进一步放大。不过，更重要的是，不同策略之间的相对优势在两类部署方式中几乎保持一致。换言之，MIAED 带来的性能改善并非特定部署条件下的偶然现象，而是来源于其本身对事务隔离强度进行按需分配的机制优势。

综合三组数据可以得到两个结论。第一，单一 SER 虽然提供了最强的一致性保证，但其保守的并发控制会明显压制系统吞吐量；将部分事务放宽到 SI-SER 后，可以取得有限但稳定的性能提升。第二，基于更细粒度事务分类的 MIAED 能够在不破坏正确性前提下显著降低不必要的强同步开销，因此在三个数据集、两种拓扑下都取得了最优吞吐量结果。这表明，混合隔离级别并不是局部优化，而是一种能够在多类工作负载上稳定发挥作用的系统级优化手段。

\section{本章小结}
本章围绕分布式 KV 数据库原型的性能表现，考察了 Courseware、SmallBank 和 TPCC 三个数据集在两种节点部署方式下的吞吐量差异，并对 SER、SI-SER 与 MIAED 三种隔离级别配置进行了对比分析。实验结果表明，当系统由单可用区集中部署转为跨可用区分散部署后，整体吞吐量会明显下降，但混合隔离级别方案在两类部署方式中都保持了稳定的相对优势，其中 MIAED 始终取得最优结果。上述测试说明，本文所设计的混合隔离级别机制能够在保证事务正确性的前提下，有效降低不必要的强同步开销，并持续提升分布式事务处理的整体效率。
