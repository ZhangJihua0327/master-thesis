\chapter{基于分布式键值数据库原型的系统测试}
本章在前述原型系统上测试不同隔离级别配置下的事务执行性能，重点观察混合隔离级别机制相较于统一强隔离方案的吞吐量变化。下文依次介绍测试环境、部署方式与评价指标，并给出三组数据集在两种部署拓扑下的实验结果。

\section{测试环境概述}
数据库原型系统基于 Golang 开发，并通过 Docker 容器模拟分布式数据库集群。测试均在本地环境中完成，容器的 CPU 与内存配额保持一致，以避免资源分配差异对结果造成额外干扰。除测试客户端外，集群共部署 6 个服务节点，包括 2 个 Router 节点、3 个 Shard 节点和 1 个 Config 节点，其中 Config 节点主要负责元数据管理。具体硬件与软件配置见表~\ref{tab:local-env-config}。

本文重点考察两种部署方式。第一种方式中，6 个服务节点全部部署在同一可用区内；第二种方式中，6 个服务节点按每两个节点一组分散部署到 3 个可用区中。两种部署方式使用相同的事务负载与资源限制，因此测试结果的差异主要反映节点分散程度对分布式事务协调开销的影响。

\section{测试负载与评价指标}
为了覆盖不同类型的事务访问模式，实验选取了 Courseware、SmallBank 和 TPCC 三个数据集，分别对应课程管理、银行转账和订单处理等场景。三组负载在读写比例、热点分布和事务冲突特征上存在差异，因此适合用来观察混合隔离级别机制在不同业务模式下的表现。

测试中比较了三种隔离级别配置。SER 表示所有事务均采用可串行化隔离级别，SI-SER 表示事务在快照隔离与可串行化之间混合执行，MIAED 则表示引入 MIA 策略后的混合隔离级别分配结果，在实验配置上对应 PC-PSI-SI-SER 的细粒度混合组合。选择 SER、SI-SER 与 PC-PSI-SI-SER 三组配置，主要是为了呼应图~\ref{fig:isolevels} 所示的隔离级别偏序关系：SER 作为统一强隔离基线，SI-SER 表示在强隔离基线上引入相邻较弱级别后的有限混合，而 PC-PSI-SI-SER 则进一步覆盖本文原型支持的主要工程级别，用于观察沿隔离级别层次逐步放宽语义约束时系统吞吐和冲突行为的变化。

其中，MIAED 中的隔离级别分配由 MIA 工具在工作负载输入阶段完成。MIA 首先根据事务模板的读集合与写集合建立静态依赖图，识别 WR、WW 和 RW 等潜在冲突依赖；随后根据静态关键环路分析结果，在保持全局鲁棒性，即整体执行仍可等价为串行化执行的前提下，为每类事务选择满足正确性要求的最低隔离级别。具体而言，纯写事务和单键只读事务可分配为 RA，多键只读事务可分配为 PC；存在读写操作但未处于危险 RW 环路中的事务可分配为 PSI；只有当事务位于可能破坏串行化的关键依赖结构中时，才保留为 SER。本文实验所使用的 \texttt{allocated\_bench\_workload} 负载即是在原始 Courseware、SmallBank 和 TPCC 负载基础上，经该静态分析与分配过程生成的结果。执行阶段的 MIAED 并不是新的并发控制协议，而是将上述已分配的隔离级别交由本文原型系统执行，用于观察更细粒度事务分配策略与本文混合隔离执行机制结合后的性能表现。

本文将 MIAED 作为扩展性对照，用于观察更细粒度事务分配策略下系统性能的变化；本章的重点仍是考察本文实现的混合隔离级别执行机制，相较于统一强隔离基线能否带来性能改善。评价指标以平均吞吐量（transactions per second, tx/s）为主，用于衡量系统在稳定运行阶段的整体处理能力；同时，本文补充统计了系统运行过程中因写写冲突或提交阶段校验失败而触发的事务回滚率（Abort Rate），以辅助分析不同负载与部署方式下的并发冲突程度。由于当前回滚率数据覆盖的是 SER 与 MIAED 两组配置，后文相关分析主要围绕这两类策略展开。

\section{测试结果与分析}

在单可用区部署下，SER 的平均吞吐量为 69.36 tx/s，SI-SER 为 74.51 tx/s，平均增幅约为 7.42\%。也就是说，即使只在 SI 和 SER 两个较强隔离级别之间做有限混合，系统也能释放一部分并发能力。作为扩展性对照，MIAED 的平均吞吐量达到 206.19 tx/s，较 SER 提升约 197.28\%，较 SI-SER 提升约 176.74\%。这一趋势在三组数据集上都较稳定：Courseware、SmallBank 和 TPCC 上相对 SER 的提升分别为 197.94\%、196.81\% 和 197.10\%。结合部署条件看，单可用区下事务协调路径较短，网络往返等待较小，因此更容易体现混合执行带来的吞吐收益。

当节点分散到多个可用区后，整体吞吐量明显下降，但不同策略之间的相对关系没有发生明显变化。SER 的平均吞吐量降至 7.13 tx/s，SI-SER 为 7.62 tx/s，平均增幅约为 6.85\%。这说明即使跨区部署显著抬高了协调开销，SI-SER 相对 SER 仍保留了稳定但有限的吞吐优势。作为扩展性对照，MIAED 的平均吞吐量为 21.17 tx/s，较 SER 提升约 196.81\%，较 SI-SER 提升约 177.78\%。分数据集来看，Courseware、SmallBank 和 TPCC 上相对 SER 的提升分别为 195.40\%、194.87\% 和 200.18\%。因此，跨区通信虽然放大了协调成本，但更细粒度的事务分配策略依旧能够取得更高吞吐量。

横向比较两种部署方式可以看到，当节点由单可用区集中部署转为跨可用区分散部署后，三种策略的平均吞吐量都降到原来的约 10\%：SER、SI-SER 和 MIAED 的降幅分别为 89.72\%、89.77\% 和 89.73\%。这一结果说明，节点分散后事务提交路径被拉长，跨节点协调与通信等待成为主导开销。不过，SI-SER 相对 SER 的优势在两类部署方式中都能观察到，说明这种混合执行方式并不依赖某一种特定拓扑；MIAED 的额外收益则提示，更细粒度的事务分配仍有进一步优化空间。

从图~\ref{fig:throughput-gain-combined} 可以更直接地看出，SI-SER 相对 SER 的收益虽然不大，但在两种部署方式和三组数据集上始终为正，提升区间约为 3.61\%--9.73\%。这说明仅在 SI 和 SER 两级之间进行混合，也能回收一部分因统一串行化而损失的并发能力。相比之下，MIAED 相对 SER 的提升接近 2 倍，单可用区下为 196.81\%--197.94\%，跨可用区下为 194.87\%--200.18\%。因此，这组结果实际上对应两类不同幅度的收益：前者来自有限的隔离级别混合，后者则来自更细粒度的事务分配。

为了进一步观察不同负载下事务冲突对执行结果的影响，本文补充统计了 SER 与 MIAED 两组配置在两种部署方式下的事务回滚率，结果如图~\ref{fig:abort-rate-combined} 所示。

从图~\ref{fig:abort-rate-combined} 可以看出，不同负载的冲突强度存在明显差异。Courseware 的回滚率最低，单可用区下 SER 和 MIAED 分别为 1.1\% 和 1.7\%，跨可用区下升至 2.1\% 和 2.5\%，整体仍处于较低水平，说明该负载中的热点写入较少。TPCC 的回滚率居中，单可用区下为 5.0\% 和 6.8\%，跨可用区下为 6.7\% 和 9.2\%。SmallBank 的回滚率最高，单可用区下 SER 与 MIAED 已分别达到 10.1\% 和 12.7\%，跨可用区下进一步上升到 13.5\% 和 16.2\%。这一结果与三类负载的事务特征基本一致：Courseware 的更新分布较分散，TPCC 存在一定程度的热点竞争，而 SmallBank 中账户读写更集中，因而更容易在提交校验阶段触发事务中止。

若比较同一负载在两种部署方式下的结果，可以发现跨可用区部署会系统性抬高回滚率。以 SER 为例，Courseware、SmallBank 和 TPCC 分别从 1.1\%、10.1\% 和 5.0\% 上升到 2.1\%、13.5\% 和 6.7\%；MIAED 也分别从 1.7\%、12.7\% 和 6.8\% 上升到 2.5\%、16.2\% 和 9.2\%。这说明跨区通信引入的额外时延会拉长事务从读取到提交的时间窗口，从而增加并发事务之间发生冲突的概率。另一方面，MIAED 在所有负载上都表现出高于 SER 的回滚率，且在高冲突负载上的差距更明显，例如 SmallBank 下两种部署方式分别高出 2.6 和 2.7 个百分点，TPCC 下分别高出 1.8 和 2.5 个百分点。这表明更积极的并发执行策略确实会带来一定的冲突代价；但结合前文吞吐量结果看，这一代价换来了更高的系统处理能力，因而整体上仍体现出较好的性能收益。

综合三组数据，可以得到两个观察。第一，单一 SER 虽然提供了更强的一致性保证，但其保守的并发控制会降低系统吞吐量；将部分事务放宽到 SI-SER 后，可以获得有限但较为稳定的性能提升。第二，MIAED 作为扩展性对照，在三个数据集和两种拓扑下均取得了最高吞吐量，这说明如果在本文机制之上进一步引入更细粒度的事务分类与分配策略，系统性能仍有继续提升的空间。

\section{本章小结}
本章比较了 Courseware、SmallBank 和 TPCC 三组负载在两种部署方式下的吞吐量与回滚率，并对 SER、SI-SER 和 MIAED 三种配置进行了分析。实验结果表明，跨可用区部署会显著拉低整体吞吐量，但 SI-SER 相对 SER 的优势在两类拓扑下都能够观察到，说明本文实现的混合隔离级别机制确实减少了部分不必要的强同步开销。回滚率结果则说明，不同负载的冲突特征差异明显，且跨区部署会放大事务中止概率；与此同时，MIAED 在获得更高吞吐量的同时，没有带来同幅度的额外冲突代价。
