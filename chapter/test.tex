\chapter{基于分布式键值数据库原型的系统测试}
本文基于前述原型系统，对不同隔离级别配置下的事务执行性能进行测试，以验证混合隔离级别机制相较于单一强隔离级别方案在吞吐量上的优势。本章首先介绍测试环境、节点部署方式与评价指标，然后给出三组数据集在两种部署拓扑下的吞吐量结果，并据此分析不同隔离级别配置的性能差异。

\section{测试环境概述}
数据库原型系统基于 Golang 开发，并通过 Docker 容器模拟分布式数据库集群。测试均在本地环境中完成，容器的 CPU 与内存配额保持一致，以避免资源分配差异对结果造成额外干扰。除测试客户端外，集群共部署 6 个服务节点，包括 2 个 Router 节点、3 个 Shard 节点和 1 个 Config 节点，其中 Config 节点主要负责元数据管理。具体硬件与软件配置见表~\ref{tab:local-env-config}。

本文重点考察两种部署方式。第一种方式中，6 个服务节点全部部署在同一可用区内；第二种方式中，6 个服务节点按每两个节点一组分散部署到 3 个可用区中。两种部署方式使用相同的事务负载与资源限制，因此测试结果的差异主要反映节点分散程度对分布式事务协调开销的影响。

\section{测试负载与评价指标}
为了更全面地考察系统在不同业务模式下的表现，本文选取了 Courseware、SmallBank 和 TPCC 三个数据集。三个数据集分别覆盖课程管理、银行转账和订单处理等不同类型的事务访问模式，能够反映混合隔离级别在多种典型负载下的适用性。

测试中比较了三种隔离级别配置。SER 表示所有事务均采用可串行化隔离级别，SI-SER 表示事务在快照隔离与可串行化之间混合执行，MIAED 则表示引入 MIA 策略后的混合隔离级别分配结果。MIA 是本组的另一项工作，主要根据事务内容分析结果，在保证事务正确性的前提下尽量匹配满足要求的最低隔离级别。本文将 MIAED 作为扩展性对照，用于观察更细粒度事务分配策略下系统性能的变化；本章的重点仍是考察本文实现的混合隔离级别执行机制，相较于统一强隔离基线能否带来性能改善。评价指标以平均吞吐量（transactions per second, tx/s）为主，用于衡量系统在稳定运行阶段的整体处理能力；同时，本文补充统计了系统运行过程中因写写冲突或提交阶段校验失败而触发的事务回滚率（Abort Rate），以辅助分析不同负载与部署方式下的并发冲突程度。由于当前回滚率数据覆盖的是 SER 与 MIAED 两组配置，后文相关分析主要围绕这两类策略展开。

从图~\ref{fig:throughput-combined} 的子图 (a) 可以看出，在所有服务节点部署于同一可用区时，SER 的平均吞吐量为 69.36 tx/s，SI-SER 为 74.51 tx/s，平均增幅约为 7.42\%。这一结果表明，即使仅在 SI 和 SER 两个较强隔离级别之间进行混合调度，系统吞吐量也有所提升。作为扩展性对照，MIAED 的平均吞吐量为 206.19 tx/s，相较于 SER 提升约 197.28\%，相较于 SI-SER 提升约 176.74\%。在三个数据集上，这一趋势较为一致：Courseware 上 MIAED 相比 SER 提升约 197.94\%，SmallBank 上提升约 196.81\%，TPCC 上提升约 197.10\%。这一现象与单可用区部署下事务协调路径较短、网络往返等待较小的实验条件相符。

当服务节点分散部署到多个可用区后，整体吞吐量明显下降，但不同隔离级别之间的相对关系基本保持不变。SER 的平均吞吐量为 7.13 tx/s，SI-SER 为 7.62 tx/s，平均增幅约为 6.85\%。这说明在跨可用区部署带来更高协调开销的条件下，SI-SER 相对 SER 仍表现出一定的吞吐优势。作为扩展性对照，MIAED 的平均吞吐量为 21.17 tx/s，相较于 SER 提升约 196.81\%，相较于 SI-SER 提升约 177.78\%。分数据集来看，MIAED 在 Courseware、SmallBank 和 TPCC 上相较于 SER 的提升分别为 195.40\%、194.87\% 和 200.18\%。结合部署条件可以看出，跨区通信会增加分布式事务的协调成本，而更细粒度的事务分配策略在该场景下仍呈现出更高的吞吐量。

进一步比较两种部署方式可以发现，当节点由单可用区集中部署转为跨可用区分散部署后，三种策略的平均吞吐量均下降到原来的约 10\%：SER 下降约 89.72\%，SI-SER 下降约 89.77\%，MIAED 下降约 89.73\%。这表明随着节点分散程度提高，事务提交路径变长，跨节点协调与通信等待的开销随之增加。与此同时，SI-SER 相对 SER 的优势在两类部署方式中均可观察到，说明该混合执行方式并不局限于单一部署场景。MIAED 的额外收益，则反映了更细粒度事务分配策略可能带来的进一步改进空间。

从图~\ref{fig:throughput-gain-combined} 可以更清楚地看到，SI-SER 相对 SER 的收益虽然有限，但在两种部署方式和三组数据集上均为正，提升区间大致位于 3.61\%--9.73\% 之间。这表明，即便只在 SI 与 SER 两级之间进行混合执行，系统仍可恢复一部分因统一串行化而受限的并发能力。相比之下，MIAED 相对 SER 的提升接近 2 倍，单可用区下为 196.81\%--197.94\%，跨可用区下为 194.87\%--200.18\%。因此，该图更适合用来区分两类现象：一类是 SI-SER 带来的有限增益，另一类是更细粒度事务分配所对应的更高吞吐量。

从图~\ref{fig:abort-rate-combined} 可以看出，不同负载对事务冲突的敏感程度存在明显差异。Courseware 的回滚率始终维持在 1\%--2\% 左右，说明该类负载下事务间写写竞争相对较弱；TPCC 的回滚率处于中间水平；而 SmallBank 在两种部署方式下都表现出最高的回滚率，其中单可用区为 10.1\% 与 10.5\%，跨可用区进一步升高到 13.5\% 与 14.0\%。这一结果与银行转账类负载中账户热点更集中、更新竞争更频繁的特点相一致，也说明高冲突工作负载会更容易触发基于版本校验的事务回滚。

进一步比较同一负载下的两种部署方式可以发现，跨可用区部署时三组数据集的回滚率均高于单可用区部署。例如，SER 在 Courseware、SmallBank 和 TPCC 上分别由 1.1\%、10.1\% 和 5.0\% 上升到 2.1\%、13.5\% 和 6.8\%；MIAED 也呈现出相同趋势。这表明当节点分散到多个可用区后，事务执行窗口会因跨区通信与协调等待而拉长，从而增加并发事务发生写写冲突的机会。另一方面，MIAED 的回滚率整体仅略高于 SER，增幅普遍在 0.1--0.5 个百分点之间，说明更细粒度的事务分配虽然提高了并发程度，但并未对应地带来大幅增加的事务中止代价。结合前述吞吐量结果，可以认为 MIAED 在获得更高吞吐量的同时，额外冲突开销仍处于较小范围内。

综合三组数据，可以得到两个观察。第一，单一 SER 虽然提供了更强的一致性保证，但其保守的并发控制会降低系统吞吐量；将部分事务放宽到 SI-SER 后，可以获得有限但较为稳定的性能提升。第二，MIAED 作为扩展性对照，在三个数据集和两种拓扑下均取得了最高吞吐量，这说明如果在本文机制之上进一步引入更细粒度的事务分类与分配策略，系统性能仍有继续提升的空间。

\section{本章小结}
本章围绕分布式键值数据库原型的性能表现，考察了 Courseware、SmallBank 和 TPCC 三个数据集在两种节点部署方式下的吞吐量差异，并对 SER、SI-SER 与 MIAED 三种隔离级别配置进行了对比分析。实验结果表明，当系统由单可用区集中部署转为跨可用区分散部署后，整体吞吐量会明显下降，但 SI-SER 相对 SER 的吞吐优势在两类部署方式中均可观察到。这说明，本文所设计的混合隔离级别执行机制在当前实验设置下能够减少部分不必要的强同步开销。补充的回滚率结果进一步表明，不同负载的冲突强度存在差异，且跨可用区部署会增加事务中止概率；同时，MIAED 在获得更高吞吐量的同时，并未表现出明显更高的额外冲突代价。MIAED 的结果也说明，在本文机制之上引入更细粒度事务分配策略，仍可能带来进一步优化。
